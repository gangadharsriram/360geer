# 2026-10-13 - Why RoMa poses fail: SfM variants and pose-error measurement (backfilled 2026-10-27)
Conversation ID: f726fa90-a7b3-4f2b-874f-392c26af976c (Claude Code)

**Headline:** the RoMa SfM pipeline (cell 8 + fundamental-matrix filter) gave poses 4.5° / 0.84 camera spacings off the original; cell size 1 + an angular essential-matrix filter cut that to 1.38° / 0.40 and lifted full-res test PSNR from 20.01 to 23.16 - still 2 dB below the original poses (25.1).

## Pose error vs the original poses (100 views, Sim3 on camera centres; `scripts/eval_pose_vs_orig.py`)

|---|---|---|---|---|
| v1: cell 8, F-filter | 100 | 4.50° | 0.84 | 15.7k |

Rotation error measured with the centre-fit is dominated by a near-constant roll offset; the gauge-free rotation error of v1 is ~1.7°.

## Findings
- OpenMVG's SfM binary only loads `matches.f/e.bin`; angular-filter output must be saved as `.e.bin` (done in the v2 script, env var `FILT`).
- Training q1_a poses+points: 0.7732 / 23.16 / 0.2507 (metrics.md S7). The first metrics.py run OOM'd (shared GPU) and was re-run on GPU 2.
- A pose-source comparison table (dataset COLMAP vs PanoVGGT vs RoMa v1/v2 vs original) was produced: dataset COLMAP agrees best with the original (0.22 spacings, 0.14° gauge-free); PanoVGGT 0.42 / 0.58°.
